## 1. 분석 파이프라인 개요

### 1.1 AnalysisPipeline 클래스 구조

`AnalysisPipeline` 클래스는 비행 통신 품질 분석의 핵심 오케스트레이터로, 업로드된 원시 데이터를 처리하여 시각화 및 보고서에 필요한 분석 결과를 생성한다.

```
analysis_pipeline.py
└── class AnalysisPipeline
    ├── __init__(session_id, upload_folder, results_folder)
    ├── validate_files()              # 파일 유효성 검사
    ├── _parse_ulg_file()            # ULG 바이너리 로그 파싱
    ├── _create_derived_variables()  # 파생 변수 생성 (속도, 거리 등)
    ├── step_1_load_data()           # 데이터 로드 및 병합
    ├── step_2_correlation_analysis() # 상관관계 분석
    ├── step_3_quality_analysis()    # 통신 품질 분석
    ├── step_4_altitude_analysis()   # 고도별 분석
    ├── step_5_generate_charts()     # 차트 생성
    └── step_6_generate_report()     # 보고서 생성
```

**초기화 파라미터:**

| 파라미터 | 타입 | 설명 |
|---------|------|------|
| `session_id` | `str` | 세션 고유 식별자 (UUID) |
| `upload_folder` | `Path` | 업로드된 파일 경로 |
| `results_folder` | `Path` | 분석 결과 저장 경로 |

**내부 디렉토리 구조:**
```
upload_folder/
├── flight_logs/    # ULG 비행 로그 파일 (필수)
├── lte_data/       # LTE 측정 CSV 파일 (선택)
└── starlink_data/  # Starlink 측정 CSV 파일 (선택)

results_folder/
├── merged_data.csv     # 병합된 분석 데이터
├── analysis_results.json
└── charts/             # 생성된 차트 이미지
```

### 1.2 전체 분석 흐름

```
[파일 업로드]
     │
     ▼
[Step 0: 파일 검증] ─── validate_files()
     │   - ULG 파일 존재 여부 확인 (필수)
     │   - LTE/Starlink CSV 파일 확인 (선택)
     │
     ▼
[Step 1: 데이터 로드 및 병합] ─── step_1_load_data()
     │   - ULG 파싱 → GPS DataFrame
     │   - LTE CSV 로드 → lte_rsrp, lte_sinr, lte_rsrq 등
     │   - Starlink CSV 로드 → starlink_latency, throughput 등
     │   - 3-way merge_asof (타임스탬프 기준, ±2초 tolerance)
     │   - 센티넬 값(-999) 필터링 → NaN 변환
     │   - 파생 변수 생성 (speed_mps, distance_from_origin)
     │
     ▼
[Step 2: 상관관계 분석] ─── step_2_correlation_analysis()
     │   - 수치형 컬럼 간 상관계수 행렬 계산
     │   - 상위 20개 상관 쌍 추출
     │
     ▼
[Step 3: 통신 품질 분석] ─── step_3_quality_analysis()
     │   - LTE 품질 통계 (RSRP, SINR, RSRQ)
     │   - Starlink 품질 통계 (latency, throughput)
     │
     ▼
[Step 4: 고도별 분석] ─── step_4_altitude_analysis()
     │   - 고도 구간별 통신 품질 상관관계
     │
     ▼
[Step 5: 차트 생성] ─── step_5_generate_charts()
     │   - 비행 프로파일, 품질 비교, 산점도 등
     │
     ▼
[Step 6: 결과 저장] ─── merged_data.csv + analysis_results.json
     │
     ▼
[API 서빙] ─── CZML / Heatmap / KPI / Signal Loss / Root Cause
```

## 2. ULG 비행 로그 변환

### 2.1 pyulog 라이브러리를 통한 바이너리 로그 파싱

ULG(ULog)는 PX4 오토파일럿이 생성하는 바이너리 형식의 비행 로그 파일이다. `pyulog` 라이브러리를 사용하여 이 바이너리 데이터를 Python DataFrame으로 변환한다.

```python
from pyulog import ULog

ulog = ULog(str(ulg_path))

# 데이터셋 탐색
for data in ulog.data_list:
    if data.name == 'vehicle_gps_position':
        gps_dataset = data
    elif data.name == 'vehicle_attitude':
        attitude_dataset = data
```

**지원 데이터셋:**
- `vehicle_gps_position`: GPS 위치 정보 (주 소스)
- `vehicle_global_position`: GPS 위치 정보 (fallback)
- `vehicle_attitude`: 자세 정보 (쿼터니언)
- `vehicle_local_position`: 로컬 좌표계 속도 데이터

### 2.2 vehicle_gps_position → GPS 좌표 추출

ULG 파일의 필드명은 PX4 버전에 따라 다를 수 있으므로 두 가지 명명 규칙을 지원한다:

```python
# 신형 PX4 (v1.13+)
if 'latitude_deg' in gps_dataset.data:
    latitudes  = gps_dataset.data['latitude_deg']   # degrees
    longitudes = gps_dataset.data['longitude_deg']  # degrees
    altitudes  = gps_dataset.data['altitude_msl_m'] # meters (MSL)
else:
    # 구형 PX4
    latitudes  = gps_dataset.data['lat']  # 1e-7 degrees (integer)
    longitudes = gps_dataset.data['lon']  # 1e-7 degrees (integer)
    altitudes  = gps_dataset.data['alt']  # mm → m 변환 필요
```

**GPS COG(Course Over Ground) 추출:**

비행 방향(헤딩) 데이터는 `cog_rad` 필드에서 추출하며, 라디안을 도(degree) 단위로 변환 후 0~360° 범위로 정규화한다:

```python
if 'cog_rad' in gps_dataset.data:
    cog_rad = gps_dataset.data['cog_rad']
    heading_deg = np.degrees(cog_rad) % 360  # 0-360도 정규화
    df['heading'] = heading_deg
```

### 2.3 vehicle_attitude → 쿼터니언에서 오일러각 변환

비행체의 3D 자세(attitude)는 쿼터니언(q0, q1, q2, q3) 형태로 저장된다. Cesium 3D 시각화 및 분석을 위해 오일러각(Roll/Pitch/Yaw)으로 변환한다.

**쿼터니언 → 오일러각 변환 공식:**

```
Roll  (X축 회전):  φ = arctan2(2(q0·q1 + q2·q3), 1 - 2(q1² + q2²))
Pitch (Y축 회전):  θ = arcsin(2(q0·q2 - q3·q1))
Yaw   (Z축 회전):  ψ = arctan2(2(q0·q3 + q1·q2), 1 - 2(q2² + q3²))
```

```python
q0, q1, q2, q3 = q['q[0]'], q['q[1]'], q['q[2]'], q['q[3]']

roll  = np.arctan2(2*(q0*q1 + q2*q3), 1 - 2*(q1**2 + q2**2))
pitch = np.arcsin(2*(q0*q2 - q3*q1))
yaw   = np.arctan2(2*(q0*q3 + q1*q2), 1 - 2*(q2**2 + q3**2))

# 라디안 → 도 변환
roll_deg  = np.degrees(roll)
pitch_deg = np.degrees(pitch)
yaw_deg   = np.degrees(yaw)
```

**결과 DataFrame 컬럼:**

| 컬럼명 | 단위 | 설명 |
|-------|------|------|
| `q0`, `q1`, `q2`, `q3` | dimensionless | 원시 쿼터니언 (3D 렌더링용) |
| `roll` | degrees | X축 회전각 |
| `pitch` | degrees | Y축 회전각 |
| `yaw` | degrees | Z축 회전각 (기수 방향) |

### 2.4 대지속도 계산

`vehicle_local_position` 데이터셋의 속도 벡터 성분을 이용하여 대지속도를 계산한다:

```
V_ground = √(vx² + vy² + vz²)
```

파이프라인에서는 GPS 좌표의 연속 포인트 간 Haversine 거리를 이용하여 파생 변수로 속도를 계산하기도 한다:

```python
# Haversine 기반 대지속도 계산
distance_moved = haversine_distance(lat_prev, lon_prev, lat_curr, lon_curr)
speed_mps = distance_moved / 0.5  # 0.5초 샘플링 간격 가정
```

### 2.5 타임스탬프 절대 시간 변환

ULG의 타임스탬프는 부팅 후 상대 시간(microseconds)이므로 절대 UTC 시간으로 변환이 필요하다. 세 가지 방법을 우선순위 순서로 시도한다:

**방법 1 (최우선): time_utc_usec 필드 직접 사용**
```python
if 'time_utc_usec' in gps_dataset.data:
    utc_times_us = gps_dataset.data['time_utc_usec']
    absolute_timestamps = pd.to_datetime(utc_times_us, unit='us', utc=True)
```

**방법 2 (Fallback): CSV 데이터 시작 시간 기준**
```python
boot_time = csv_start_time - pd.Timedelta(microseconds=int(ulog_start_us))
absolute_timestamps = [boot_time + pd.Timedelta(microseconds=int(ts))
                       for ts in timestamps_us]
```

**방법 3 (최후 수단): 파일명에서 KST 시간 추출**
```python
# 파일명 패턴: YYYYMMDD_HHMM
# KST → UTC 변환 (UTC = KST - 9시간)
match = re.search(r'(\d{8})_(\d{4})', filename)
kst_time = datetime.strptime(f'{date_str}_{time_str}', '%Y%m%d_%H%M')
boot_time = pd.Timestamp(kst_time - timedelta(hours=9), tz='UTC')
```

## 3. 다중 소스 타임스탬프 병합

### 3.1 서로 다른 샘플링 주기 데이터 정렬

비행 로그(GPS), LTE 측정, Starlink 측정은 각각 서로 다른 샘플링 주기로 데이터를 수집한다:

| 데이터 소스 | 일반적인 샘플링 주기 | 샘플링 방식 |
|------------|-------------------|------------|
| ULG GPS | 1~10 Hz | 연속 (PX4 로거) |
| LTE 측정 | 1 Hz | 폴링 방식 |
| Starlink 측정 | 1 Hz | gRPC API 폴링 |

### 3.2 최근접 타임스탬프 매칭 알고리즘 (merge_asof)

pandas의 `merge_asof` 함수를 사용하여 타임스탬프 기반 최근접 이웃 매칭을 수행한다. GPS 데이터를 기준(left) 테이블로 삼아 순차적으로 병합한다:

```python
# Step 1: GPS를 기준으로 시작
merged = flight_data.copy()

# Step 2: Starlink 병합 (±2초 tolerance)
merged = pd.merge_asof(
    merged.sort_values('timestamp'),
    starlink_data.sort_values('timestamp'),
    on='timestamp',
    direction='nearest',  # 가장 가까운 타임스탬프 매칭
    tolerance=pd.Timedelta('2s')  # 2초 이상 차이나면 NaN
)

# Step 3: LTE 병합 (±2초 tolerance)
merged = pd.merge_asof(
    merged.sort_values('timestamp'),
    lte_data.sort_values('timestamp'),
    on='timestamp',
    direction='nearest',
    tolerance=pd.Timedelta('2s')
)
```

**Tolerance 설정 근거:** GPS와 통신 데이터 간 최대 허용 시간 차이를 2초로 설정하여, 통신 데이터 수집 지연 및 시스템 클럭 차이를 수용하면서도 시간적으로 무관한 데이터가 잘못 병합되는 것을 방지한다.

### 3.3 GPS 데이터 없는 경우의 처리

GPS 데이터 추출에 실패한 경우, LTE와 Starlink 데이터만으로 outer join 병합을 수행한다:

```python
merged = pd.merge(
    starlink_data,
    lte_data,
    on='timestamp',
    how='outer',
    suffixes=('', '_duplicate')
).sort_values('timestamp').reset_index(drop=True)
```

### 3.4 센티넬 값 필터링

센서 오류를 나타내는 센티넬 값을 NaN으로 변환한다:

| 컬럼 | 센티넬 값 | 의미 |
|------|---------|------|
| `lte_rssi` | -999 | 센서 오류 / LTE 미연결 |
| `lte_rsrp` | -999 또는 ≥ 0 | 센서 오류 / LTE 미연결 |
| `lte_rsrq` | -999 또는 ≥ 0 | 센서 오류 / LTE 미연결 |
| `lte_sinr` | -999 | 센서 오류 |
| `starlink_snr` | -999 | SNR 측정 불가 |
| `starlink_pop_ping_latency_ms` | -1 | 핑 측정 실패 |

**좌표 보간:** 병합 후 GPS 좌표(위도, 경도, 고도)의 NaN 값은 선형 보간으로 처리한다:

```python
self.merged_data['altitude']  = merged['altitude'].interpolate(method='linear', limit_direction='both')
self.merged_data['latitude']  = merged['latitude'].interpolate(method='linear', limit_direction='both')
self.merged_data['longitude'] = merged['longitude'].interpolate(method='linear', limit_direction='both')
```

### 3.5 Sortie(시나리오) 자동 감지

복수의 ULG 파일이 업로드된 경우, 각 파일에 고유한 `flight_id`를 부여하여 개별 비행 소티를 구분한다:

```python
for flight_idx, ulg_path in enumerate(sorted(flight_log_files)):
    gps_df = self._parse_ulg_file(ulg_path, csv_start_time)
    if gps_df is not None:
        gps_df['flight_id']   = flight_idx        # 0, 1, 2, ...
        gps_df['flight_name'] = ulg_path.stem     # 파일명 (확장자 제외)
```

전체 GPS 데이터는 `flight_id` → `timestamp` 순으로 정렬하여 일관성을 보장한다.

## 4. LTE 복합 품질 점수 (CQS)

### 4.1 개요

LTE Composite Quality Score (CQS)는 BVLOS(가시권 외 비행) 드론의 C2(Command & Control) 링크 품질을 정량화하기 위한 복합 지표이다. 3GPP 및 GSMA ACJA 표준에 기반하여 설계되었다.

**구현 위치:** `analysis/api/threed/czml_generator.py` - `compute_lte_cqs_scores()` 함수

### 4.2 CQS 계산 공식

**Throughput 데이터 가용 시 (Full Formula):**
```
CQS = RSRP_norm × 0.25 + RSRQ_norm × 0.25 + SINR_norm × 0.30 + Throughput_norm × 0.20
```

**Throughput 데이터 미가용 시 (Fallback Formula):**
```
CQS = RSRP_norm × 0.3125 + RSRQ_norm × 0.3125 + SINR_norm × 0.375
```

*Fallback 가중치는 Full Formula의 RSRP:RSRQ:SINR 비율(25:25:30)을 Throughput 제외 후 80%→100%로 비례 증가시킨 결과다.*

### 4.3 각 메트릭의 정규화 범위

각 LTE 파라미터를 0~1 범위로 정규화한다 (높은 값 = 좋은 품질 = 1):

| 파라미터 | 측정 범위 | 정규화 공식 |
|---------|---------|-----------|
| RSRP (Reference Signal Received Power) | -140 ~ -40 dBm | `clip((rsrp + 140) / 100, 0, 1)` |
| SINR (Signal-to-Interference-plus-Noise Ratio) | -20 ~ 30 dB | `clip((sinr + 20) / 50, 0, 1)` |
| RSRQ (Reference Signal Received Quality) | -20 ~ -3 dB | `clip((rsrq + 20) / 17, 0, 1)` |
| Throughput | 0 ~ P95 | `clip(flow / p95, 0, 1)` |

**Throughput 정규화 특이사항:**
rx_bytes와 tx_bytes의 누적 카운터 차분(diff)을 사용하여 순간 처리량을 계산하고, 상위 95 퍼센타일 값으로 정규화한다:

```python
rx_diff = np.diff(rx, prepend=rx[0]).clip(min=0)
tx_diff = np.diff(tx, prepend=tx[0]).clip(min=0)
total_flow = rx_diff + tx_diff
p95 = np.nanpercentile(total_flow[total_flow > 0], 95)
throughput_norm = np.clip(total_flow / p95, 0, 1)
```

### 4.4 무효 데이터 필터링

센티넬 값 및 물리적으로 불가능한 값을 NaN으로 처리한다:

```python
rsrp = np.where((rsrp <= -999) | (rsrp >= 0), np.nan, rsrp)  # -999 이하 및 0 이상 제외
sinr = np.where(sinr <= -999, np.nan, sinr)                   # -999 이하 제외
rsrq = np.where((rsrq <= -999) | (rsrq >= 0), np.nan, rsrq)  # -999 이하 및 0 이상 제외
```

**LTE 미연결 감지:** RSRP가 0 이상인 값은 LTE에 연결되지 않은 상태(센서가 반환하는 기본값)이므로 제외한다.

**전체 NaN 처리:** 세 파라미터 모두 NaN인 경우(LTE 완전 미연결), CQS도 NaN으로 설정한다:

```python
all_nan = np.isnan(rsrp) & np.isnan(sinr) & np.isnan(rsrq)
scores = np.where(all_nan, np.nan, scores)
```

### 5.1 DL Throughput 정규화

### 5.2 Latency 역방향 정규화

Starlink latency는 낮을수록 좋은 품질이므로 정규화 후 반전(inversion)한다:

```
Starlink_Latency_norm = clip((200 - latency) / 200, 0, 1)
```

즉, latency = 0ms → 정규화 값 = 1.0 (최고), latency = 200ms → 정규화 값 = 0.0 (최저).

```python
# hexagonal_heatmap.py의 정규화 로직
normalized = (values - vmin) / (vmax - vmin)  # vmin=0, vmax=200
if 'latency' in mode:
    normalized = 1 - normalized  # 역방향 정규화
```

### 5.3 Packet Loss Rate 분석

Starlink ping drop rate를 이용하여 패킷 손실율을 분석한다:

```python
# 패킷 손실율 정규화 (1.0 = 100% 손실, 0.0 = 무손실)
# 역방향: 낮은 손실 = 높은 품질
packet_loss_norm = clip((1.0 - packet_loss) / (0.0 - 1.0), 0, 1)
```

**커스텀 메트릭 컬럼 이름:**
- `starlink_ping_drop_rate`: Starlink gRPC API의 ping drop rate
- `starlink_raw_status.fraction_obstructed`: 위성 신호 차단 비율

### 5.4 Obstruction Percentage 분석

위성 신호 차단 비율(`fraction_obstructed`)은 드론 위치의 하늘 가시성을 나타낸다:

### 9.2 총 비행 거리 (Haversine 공식)

GPS 포인트 간 연속적인 Haversine 거리를 합산하여 총 비행 거리를 계산한다:

```
d = 2R × arctan2(√a, √(1-a))

where:
  a = sin²(Δφ/2) + cos(φ₁) × cos(φ₂) × sin²(Δλ/2)
  R = 6371 km (지구 반경)
  φ = 위도 (radians)
  λ = 경도 (radians)
```

```python
def calculate_total_distance(df: pd.DataFrame) -> float:
    total_distance = 0.0
    for i in range(1, len(df)):
        lat1 = radians(df.iloc[i-1]['latitude'])
        lon1 = radians(df.iloc[i-1]['longitude'])
        lat2 = radians(df.iloc[i]['latitude'])
        lon2 = radians(df.iloc[i]['longitude'])

        dlat = lat2 - lat1
        dlon = lon2 - lon1

        a = sin(dlat/2)**2 + cos(lat1) * cos(lat2) * sin(dlon/2)**2
        c = 2 * atan2(sqrt(a), sqrt(1-a))

        total_distance += 6371 * c  # km 단위

    return total_distance
```

## 10. 기지국 위치 추정

### 10.1 COST-231 Hata 경로 손실 모델

**구현 위치:** `analysis/api/threed/tower_estimation.py`

RSRP(수신 신호 강도)에서 드론과 LTE 기지국 간 거리를 추정하기 위해 Urban COST-231 Hata 경로 손실 모델을 사용한다:

**경로 손실 공식:**
```
PL(dB) = 46.3 + 33.9×log₁₀(f) - 13.82×log₁₀(hb) + [44.9 - 6.55×log₁₀(hb)]×log₁₀(d)
```

**파라미터:**
| 파라미터 | 기본값 | 설명 |
|---------|-------|------|
| `f` | 1800 MHz | LTE 주파수 (Band 3 기준) |
| `hb` | 30 m | 기지국 안테나 높이 |
| `tx_power_dbm` | 43 dBm | 기지국 송신 전력 |

**거리 역산:**
```
PL = TX_power - RSRP
d = 10^((PL - A) / B)

where:
  A = 46.3 + 33.9×log₁₀(f) - 13.82×log₁₀(hb)
  B = 44.9 - 6.55×log₁₀(hb)
```

```python
def rsrp_to_distance_m(rsrp_dbm, frequency_mhz=1800, tx_power_dbm=43):
    path_loss   = tx_power_dbm - rsrp_dbm
    hb          = 30
    A = 46.3 + 33.9 * np.log10(frequency_mhz) - 13.82 * np.log10(hb)
    B = 44.9 - 6.55 * np.log10(hb)
    distance_km = 10 ** ((path_loss - A) / B)
    distance_m  = distance_km * 1000
    return max(50, min(distance_m, 10000))  # 50m ~ 10km 범위로 제한
```

### 10.2 3중 추정 방법

#### 방법 1: Trilateration (삼변측량)

최소자승 최적화를 통해 기지국 위치를 추정한다. RSRP 상위 10개 포인트를 사용하며, `soft_l1` 손실 함수로 이상치에 강인한(robust) 최적화를 수행한다:

```python
def residuals(tower_pos):
    tower_lat, tower_lon, tower_alt = tower_pos
    errors = []
    for i in range(len(lats)):
        calc_dist = haversine_distance_m(lats[i], lons[i], alts[i],
                                        tower_lat, tower_lon, tower_alt)
        error = distances[i] - calc_dist  # 추정 거리 - 계산 거리
        errors.append(error)
    return errors

result = least_squares(
    residuals,
    [init_lat, init_lon, 30.0],       # 초기값: 최강 신호 포인트
    bounds=([-90, -180, 0], [90, 180, 100]),
    loss='soft_l1',                    # 이상치에 강인한 손실 함수
    ftol=1e-6, xtol=1e-6
)
```

**신뢰도 산출:**
```python
confidence = 1.0 / (result.cost + 1)       # 비용 역수
uncertainty_m = float(np.std(final_errors)) # 잔차 표준편차
```

#### 방법 2: Weighted Centroid (가중 중심)

RSRP 값을 가중치로 사용하여 드론 GPS 위치들의 가중 평균을 기지국 위치로 추정한다:

```python
weights = cell_data['lte_rsrp'] + 140   # -140dBm=0, -40dBm=100
weights = np.maximum(weights, 1)         # 음수 방지

tower_lat = float(np.average(cell_data['latitude'],  weights=weights))
tower_lon = float(np.average(cell_data['longitude'], weights=weights))
```

강한 신호(높은 RSRP) = 기지국에 가까운 위치에 더 높은 가중치를 부여한다.

#### 방법 3: Top-N Signal Average

가장 강한 신호를 수신한 상위 N개 GPS 포인트의 단순 평균을 기지국 위치로 추정한다:

```python

tower_lat = float(top_points['latitude'].mean())
tower_lon = float(top_points['longitude'].mean())
```

GPS 노이즈에 가장 강인한(robust) 방법이며, 기본 신뢰도 0.8을 부여한다.

### 10.3 Hybrid Consensus (하이브리드 합의)

세 가지 방법의 결과를 신뢰도 가중 평균으로 통합한다:

```python
def estimate_tower_hybrid(cell_data, verbose=True):
    results = []

    # Method 1: Weighted Centroid (confidence=0.7)
    result1 = estimate_tower_weighted_centroid(cell_data)
    results.append(result1)

    # Method 2: Top 3 Average (confidence=0.8)
    result2 = estimate_tower_top_average(cell_data, top_n=3)
    results.append(result2)

    # Method 3: Trilateration (confidence=1/(cost+1))
    if len(cell_data) >= 5:
        result3 = estimate_tower_trilateration(cell_data)
        if result3:
            results.append(result3)

    # 신뢰도 가중 평균
    total_conf = sum(r['confidence'] for r in results)
    final_lat = sum(r['lat'] * r['confidence'] for r in results) / total_conf
    final_lon = sum(r['lon'] * r['confidence'] for r in results) / total_conf
    final_alt = sum(r['alt'] * r['confidence'] for r in results) / total_conf

    # 불확실도: 방법들 간 표준편차와 각 방법의 평균 불확실도 중 큰 값 선택
    consensus_uncertainty_m = np.sqrt(std_lat**2 + std_lon**2) * 111000
    avg_uncertainty_m = sum(r['uncertainty_m'] for r in results) / len(results)
    final_uncertainty_m = max(consensus_uncertainty_m, avg_uncertainty_m)
```

### 10.4 eNodeB 기반 그룹핑

물리적 기지국(eNodeB)은 여러 섹터(방향별 안테나)를 가질 수 있다. 같은 eNodeB ID를 가진 모든 섹터의 데이터를 통합하여 추정 정확도를 향상시킨다:

```python
def estimate_tower_by_enodeb(merged_data, enodeb_id, sector_cells, verbose=True):
    all_sector_data = []

    for sector_id, cell_id in sector_cells.items():
        sector_data = merged_data[merged_data['lte_cell_id'] == cell_id]
        # 유효 RSRP 범위 필터링 (-140 ~ -40 dBm)
        sector_data = sector_data[(sector_data['lte_rsrp'] >= -140) &
                                  (sector_data['lte_rsrp'] <= -40)]
        if len(sector_data) > 0:
            all_sector_data.append(sector_data)

    combined_data = pd.concat(all_sector_data, ignore_index=True)

    # 상위 50% RSRP 데이터만 사용 (신호 품질 필터링)
    combined_data = filter_by_signal_quality(combined_data, rsrp_percentile=50.0)

    # 최소 3개 포인트 이상인 경우만 추정
    if len(combined_data) >= 3:
        return estimate_tower_hybrid(combined_data, verbose=False)
```

### 11.5 Run-Length Encoding (RLE) 경로 압축

동일한 색상의 연속 포인트들을 하나의 polyline entity로 병합하여 CZML 파일 크기와 렌더링 부하를 대폭 절감한다:

```python
run_color = None
run_pts   = []

for i in range(0, num_points, segment_interval):
    pt        = (lon, lat, alt)
    color_key = tuple(colors[i].tolist())

    if color_key == run_color:
        run_pts.append(pt)      # 같은 색상: 현재 run에 추가
    else:
        flush_run(run_color, run_pts)  # 색상 변경: 현재 run 출력
        run_color = color_key
        run_pts   = [run_pts[-1], pt]  # 연속성을 위한 마지막 포인트 오버랩
```

**효과:** 10,000개 포인트 → 수백 개 RLE 세그먼트로 압축 (CZML 파일 크기 약 3배 절감)
