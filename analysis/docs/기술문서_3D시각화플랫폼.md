## 1. 플랫폼 개요

본 플랫폼은 드론 비행 경로와 통신 품질 데이터를 Cesium.js 기반 3D 지구본 위에 시각화하는 웹 애플리케이션이다. 비행 로그(ULG), LTE 모뎀 데이터, Starlink 위성 단말 데이터를 통합 분석한 결과를 실시간 3D 렌더링으로 제공한다.

### 핵심 기능

| 기능 | 설명 |
|------|------|
| 3D 비행 경로 | Cesium 지구본 위 고도 반영 3D 경로 표시 |
| 20+ 컬러 모드 | 고도, 속도, LTE/Starlink 품질 등 다양한 지표별 경로 색상 |
| H3 헥사곤 히트맵 | 공간 집계 기반 통신 품질 3D 히트맵 |
| 비행 플레이백 | Cesium Timeline 기반 시간축 재생 및 항공기 추적 |
| 기지국 시각화 | 신호 데이터 기반 추정 기지국 위치 및 연결선 |
| 신호 손실 표시 | 통신 두절 구간 3D 마커 |
| KPI 대시보드 | 비행/신호 통계 실시간 요약 |
| 근본 원인 분석 | 신호 손실 원인 분류 및 분포 |
| Sortie/Lap 필터 | 개별 비행 및 왕복 구간 선택 |
| 전체 세션 통합 히트맵 | 다중 세션 데이터 결합 시각화 |

## 3. 백엔드 API 서버

Flask Blueprint 기반 REST API 서버로, 모든 시각화 데이터를 JSON/CZML 형식으로 제공한다.

### 3.1 API 엔드포인트 목록

| 엔드포인트 | 메서드 | 설명 | 응답 형식 |
|-----------|--------|------|----------|
| `/api/3d/flights` | GET | 전체 비행 세션 목록 | JSON Array |
| `/api/3d/flights/{session_id}` | GET | 세션 메타데이터 | JSON Object |
| `/api/3d/flights/{session_id}/scenarios` | GET | 세션 내 개별 비행(Sortie) 목록 | JSON Array |
| `/api/3d/czml/{session_id}` | GET | 비행 경로 CZML 데이터 | CZML Document |
| `/api/3d/heatmap/{session_id}` | GET | 헥사곤 히트맵 CZML | CZML Document |
| `/api/3d/heatmap/all-sessions` | GET | 전체 세션 통합 히트맵 | CZML Document |
| `/api/3d/cell-towers/{session_id}` | GET | 추정 기지국 위치 | JSON Array |
| `/api/3d/kpi/{session_id}` | GET | KPI 요약 통계 | JSON Object |
| `/api/3d/signal-loss/{session_id}` | GET | 신호 손실 구간 | JSON Object |
| `/api/3d/root-cause/{session_id}` | GET | 근본 원인 분석 | JSON Object |

### 3.2 CZML 엔드포인트 쿼리 파라미터

`/api/3d/czml/{session_id}` 엔드포인트는 다음 쿼리 파라미터를 지원한다:

| 파라미터 | 타입 | 기본값 | 설명 |
|---------|------|--------|------|
| `sample_rate` | float | 1.0 | 샘플링 레이트 (Hz) |
| `color_by` | string | "altitude" | 경로 컬러링 기준 (20+ 모드) |
| `flight_id` | int | null | 특정 Sortie 필터 |
| `lap` | int | 0 | Lap 필터 (0=전체, 1=1회차, 2=2회차) |
| `custom_metrics` | JSON string | null | 사용자 정의 가중치 |
| `heading_offset` | float | 0 | 기수 방위각 보정값 (도) |
| `pitch_offset` | float | 0 | 피치 보정값 (도) |
| `roll_offset` | float | 0 | 롤 보정값 (도) |

### 3.3 히트맵 엔드포인트 쿼리 파라미터

`/api/3d/heatmap/{session_id}` 엔드포인트:

| 파라미터 | 타입 | 기본값 | 설명 |
|---------|------|--------|------|

## 4. CZML 생성 엔진

### 4.1 CZML 개요

CZML (Cesium Language)은 Cesium.js에서 시간축 기반 3D 객체를 기술하는 JSON 형식이다. 본 시스템은 비행 경로를 시간-위치-색상 정보가 포함된 CZML polyline으로 변환한다.

### 4.2 적응형 샘플링

데이터 크기에 따라 렌더링 성능을 최적화하는 자동 샘플링 로직을 적용한다. 목표 렌더링 포인트: 5,000~15,000개.

| 데이터 크기 | 샘플링 비율 | 세그먼트 간격 | 예상 세그먼트 수 |
|-----------|-----------|-------------|--------------|
| >100,000 | 5% | 5포인트 | ~1,000 |
| >50,000 | 10% | 3포인트 | ~1,666 |
| >20,000 | 20% | 2포인트 | ~2,000 |
| >10,000 | 30% | 1포인트 | ~3,000 |
| ≤10,000 | 100% | 1포인트 | 전체 |

**샘플링 예외 모드**: 다음 컬러 모드는 희소 이벤트 보존을 위해 샘플링을 건너뛴다:
- `lte_quality_combined`, `starlink_quality_combined`
- `lte_band`, `lap_number`
- `starlink_connection_quality`, `starlink_roaming`, `starlink_alerts_any`

### 4.3 CZML 문서 구조

```json
[
  {
    "id": "document",
    "name": "Flight Path",
    "version": "1.0",
    "clock": {
      "interval": "2026-02-12T06:30:00Z/2026-02-12T08:00:00Z",
      "currentTime": "2026-02-12T06:30:00Z",
      "multiplier": 10
    }
  },
  {
    "id": "flight-path",
    "name": "Flight",
    "polyline": {
      "positions": {
        "cartographicDegrees": [lon, lat, alt, lon, lat, alt, ...]
      },
      "material": {
        "polylineOutline": {
          "color": { "rgba": [R, G, B, A, R, G, B, A, ...] }
        }
      },
      "width": 3
    },
    "position": {
      "epoch": "2026-02-12T06:30:00Z",
      "cartographicDegrees": [time, lon, lat, alt, ...]
    },
    "orientation": {
      "epoch": "2026-02-12T06:30:00Z",
      "unitQuaternion": [time, x, y, z, w, ...]
    },
    "model": {
      "gltf": "/models/drone.glb",
      "scale": 50
    }
  }
]
```

### 4.4 세그먼트별 컬러링

경로는 세그먼트 단위로 분할되며, 각 세그먼트에 해당 지표 값에 따른 색상이 할당된다. RLE(Run-Length Encoding) 압축을 적용하여 연속 동일 색상 구간을 병합, CZML 크기를 최대 60% 절감한다.

```
세그먼트 생성 흐름:
GPS 포인트 → 세그먼트 간격으로 그룹핑 → 각 세그먼트 평균값 계산
→ 도메인별 정규화 (0~1) → Jet Colormap 매핑 → RGBA 색상 할당
→ RLE 압축 → CZML polyline material
```

### 4.5 Lap 경계 감지

세션 내 왕복(Lap) 비행을 자동 감지하여 1회차/2회차를 분리 분석한다. 감지 알고리즘은 시작 지점으로의 재접근을 GPS 거리 기반으로 판별한다.

## 5. 경로 컬러 모드

20개 이상의 컬러 모드를 지원하며, 각 모드는 도메인별 정규화 범위와 Jet Colormap을 사용한다.

### 5.1 비행 지표

| 모드 | 설명 | 정규화 범위 | 비고 |
|------|------|-----------|------|
| `altitude` | GPS 고도 | 실측 min~max | 높을수록 빨강 |
| `speed` | 대지속도 | 실측 min~max | 빠를수록 빨강 |
| `pitch` | 피치각 | -30~+30도 | |
| `roll` | 롤각 | -45~+45도 | |
| `pitch_performance` | 피치 안정성 | 동적 | |
| `lap_number` | 왕복 구분 | 1 또는 2 | 이진 컬러 |

### 5.2 LTE 품질 지표

| 모드 | 설명 | 정규화 범위 | 방향 |
|------|------|-----------|------|
| `lte_composite_quality` | CQS 복합 점수 | 0~1 | 높을수록 좋음 |
| `lte_rsrp` | 기준 신호 수신 전력 | -140 ~ -40 dBm | 높을수록 좋음 |
| `lte_sinr` | 신호대간섭잡음비 | -20 ~ 30 dB | 높을수록 좋음 |
| `lte_rsrq` | 기준 신호 수신 품질 | -20 ~ -3 dB | 높을수록 좋음 |
| `lte_rssi` | 수신 신호 강도 | -120 ~ -20 dBm | 높을수록 좋음 |
| `lte_band` | LTE 밴드 번호 | 밴드별 색상 | 범주형 |
| `lte_outage` | LTE 두절 구간 | 이진 | 두절=빨강 |
| `lte_packet_loss_rate` | 패킷 손실률 | 0~1 | 높을수록 나쁨 |
| `lte_quality_combined` | 종합 품질 등급 | 5단계 | 범주형 |

### 5.3 Starlink 품질 지표

| 모드 | 설명 | 정규화 범위 | 방향 |
|------|------|-----------|------|
| `starlink_latency` | 위성 왕복 지연 | 200 ~ 0 ms | **역방향** (낮을수록 좋음) |
| `starlink_throughput_down` | 다운링크 처리량 | 0 ~ 50 Mbps | 높을수록 좋음 |
| `starlink_throughput_up` | 업링크 처리량 | 0 ~ 50 Mbps | 높을수록 좋음 |
| `starlink_packet_loss` | 핑 손실률 | 0 ~ 1 | 높을수록 나쁨 |
| `starlink_obstruction` | 장애물 차폐율 | 0 ~ 100% | 높을수록 나쁨 |
| `starlink_uptime` | 연결 유지 시간 | 동적 | 길수록 좋음 |
| `starlink_quality_combined` | 종합 품질 등급 | 5단계 | 범주형 |

### 5.4 통합 지표

| 모드 | 설명 | 산출 방법 |
|------|------|---------|
| `combined_connectivity` | 통합 연결 품질 | nanmax(LTE CQS, Starlink DL norm) |

### 5.5 Jet Colormap 정의

11개 제어점으로 구성된 연속 컬러맵:

| 정규화 값 | RGB | 색상 |
|----------|-----|------|
| 0.00 | (0, 0, 143) | 짙은 파랑 |
| 0.10 | (0, 0, 255) | 파랑 |
| 0.25 | (0, 128, 255) | 시안 |
| 0.40 | (0, 255, 255) | 밝은 시안 |
| 0.50 | (0, 255, 128) | 시안-초록 |
| 0.60 | (0, 255, 0) | 초록 |
| 0.70 | (128, 255, 0) | 황록 |
| 0.80 | (255, 255, 0) | 노랑 |
| 0.90 | (255, 128, 0) | 주황 |
| 0.95 | (255, 64, 0) | 짙은 주황 |
| 1.00 | (255, 0, 0) | 빨강 |

해석 규칙: 파랑(나쁨/낮음) → 빨강(좋음/높음). Starlink latency는 역방향(낮을수록 빨강).

## 6. H3 헥사곤 히트맵

### 6.1 H3 공간 인덱싱

Uber H3 라이브러리를 사용한 헥사곤 격자 기반 공간 집계 시스템이다. GPS 좌표를 H3 셀에 매핑하고, 셀별 통신 품질 메트릭을 집계하여 3D 히트맵으로 시각화한다.

### 6.2 H3 해상도별 격자 크기

| 해상도 | 변 길이 | 셀 면적 | 용도 |
|--------|---------|---------|------|
| 7 | 1.22 km | 3.87 km² | 광역 분석 |
| 8 | 461 m | 737,327 m² | 중역 분석 |
| **9** | **174 m** | **105,332 m²** | **기본값 (1km 이하 경로에 적합)** |
| 10 | 66 m | 15,047 m² | 정밀 분석 |

### 6.3 히트맵 유형

| 유형 | 메트릭 | 정규화 범위 | 설명 |
|------|--------|-----------|------|
| `lte` | LTE CQS | 0 ~ 1 | LTE 복합 품질 점수 |
| `starlink` | DL throughput | 0 ~ 50 Mbps | Starlink 다운링크 처리량 |
| `combined` | nanmax(CQS, DL norm) | 0 ~ 1 | 두 통신 중 최선 품질 |

### 6.4 집계 방법

| 방법 | 설명 | 용도 |
|------|------|------|
| `mean` | 셀 내 평균값 | 일반적 품질 분포 확인 (기본값) |
| `max` | 셀 내 최댓값 | 최상 품질 도달 가능 지점 확인 |
| `min` | 셀 내 최솟값 | 최악 품질 지점 확인 |
| `median` | 셀 내 중앙값 | 이상치 영향 제거 |

### 6.5 3D 고도 구간 (Altitude Binning)

히트맵은 고도별로 분리 집계가 가능하다. `altitude_bin_size` 파라미터로 고도 구간 크기를 설정하며, 기본값은 25m이다.

```
고도 25m 구간 예시:
0~25m   → H3 셀 집합 A (지상 근처)
25~50m  → H3 셀 집합 B
...
275~300m → H3 셀 집합 L (고고도)

각 구간이 독립적인 히트맵 레이어로 3D 공간에 표시됨
```

### 6.6 전체 세션 통합 히트맵

`/api/3d/heatmap/all-sessions` 엔드포인트는 모든 완료된 세션의 데이터를 결합하여 단일 히트맵을 생성한다. 동일 H3 셀에 복수 세션 데이터가 존재할 경우 선택된 집계 방법으로 통합한다.

### 6.7 CZML 출력 구조

각 H3 헥사곤 셀은 CZML polygon으로 변환된다:

```json
{
  "id": "hex-89283082837ffff-alt150",
  "polygon": {
    "positions": {
      "cartographicDegrees": [lon1, lat1, alt, lon2, lat2, alt, ...]
    },
    "material": {
      "solidColor": {
        "color": { "rgba": [255, 128, 0, 180] }
      }
    },
    "height": 150,
    "extrudedHeight": 175,
    "outline": false
  }
}
```

## 7. 부가 시각화 레이어

### 7.1 기지국 위치 추정 및 시각화

신호 데이터(RSRP, PCI, eNodeB ID)로부터 기지국 위치를 추정하고 지구본 위에 표시한다.

**추정 알고리즘**:
1. COST-231 Hata 경로 손실 모델로 RSRP → 거리 변환
2. 3중 추정: Trilateration, Weighted Centroid, Top-N Average
3. Hybrid Consensus로 최종 위치 결정 (신뢰도 점수 부여)

**시각화 요소**:
- 기지국 위치 마커 (빌보드 아이콘)
- 드론 경로 ↔ 기지국 연결선 (시간축 기반)
- PCI별 색상 구분

### 7.2 신호 손실 구간 시각화

통신 두절 구간을 3D 마커로 지구본 위에 표시한다.

**감지 기준**:
- LTE: RSRP < -110 dBm
- Starlink: latency > 150 ms

**표시 정보**:
- 구간 중심 좌표 및 고도
- 지속 시간
- 원인 분류 (LTE only / Starlink only / Both)

### 7.3 위성 방향 시각화

Starlink 단말의 위성 방향 데이터를 CZML로 시각화한다. 안테나 지향 방향을 3D 벡터로 표시하여 장애물 차폐 분석에 활용한다.


### 8.2 CesiumViewer (핵심 컴포넌트)

Cesium.js Viewer 인스턴스를 관리하는 최상위 3D 렌더링 컴포넌트.

**주요 기능**:

| 기능 | 구현 |
|------|------|
| CZML 로딩 | `CzmlDataSource.load()` → polyline + model + clock |
| 히트맵 레이어 | LTE/Starlink/Combined 각각 독립 DataSource |
| 기지국 표시 | Entity 생성 (billboard + label) |
| 신호 손실 마커 | Entity 생성 (sphere + label) |
| 카메라 모드 | Free 회전 / 항공기 추적 (trackedEntity) |
| 비행 플레이백 | Cesium Clock + Timeline 위젯 |

**카메라 모드**:
- `free`: 사용자 자유 회전/줌, 전체 경로 조감
- `track`: 항공기 엔터티 자동 추적, 시점 고정 추종

### 8.3 UnifiedControlPanel (통합 제어)

모든 시각화 파라미터를 제어하는 통합 패널.

**제어 그룹**:

| 그룹 | 제어 항목 |
|------|---------|
| 세션 선택 | 세션 목록, 비행 시간 범위 표시 (KST 변환) |
| 경로 컬러 | 20+ 컬러 모드 드롭다운, 커스텀 가중치 빌더 |
| 히트맵 | LTE/Starlink/Combined 토글 (상호 배타), 전체 세션 모드 |
| 헥사곤 파라미터 | 해상도(7-10), 집계 방법, 고도 구간 크기 |
| Sortie 필터 | 개별 비행 선택 / 전체 |
| Lap 필터 | 전체 / 1회차 / 2회차 |
| 카메라 | Free / Track 모드 전환 |
| 부가 레이어 | 기지국, 연결선, 신호 손실, 위성 방향 토글 |

### 8.4 KPIDashboard

실시간 KPI 요약 통계를 카드 형태로 표시한다.

| KPI 카테고리 | 항목 |
|------------|------|
| 비행 | 총 비행시간, 비행거리(km), 최대고도(m), 평균속도(km/h) |
| LTE | 평균 RSRP, 품질 등급 (색상 코드) |
| Starlink | 평균 latency, 품질 등급 (색상 코드) |
| 신호 손실 | 전체 대비 비율(%), 세그먼트 수, 총 손실 시간(초) |

### 8.5 RootCausePanel

신호 손실 원인을 분석하여 시각화한다.

- **원인 분류**: LTE only / Starlink only / Both (파이 차트)
- **고도 분포**: 고도대별 신호 손실 빈도 (바 차트)
- **시간 분포**: 시간대별 패턴
- **요약 통계**: 총 세그먼트 수, 평균 지속시간, 총 영향 시간

### 8.6 AnalyticsPanel

LTE 및 Starlink 신호 메트릭의 상세 통계 분석을 제공한다. 히스토그램, 시계열 트렌드, 상관관계 차트 등을 포함한다.

### 8.7 AttitudeAnalysisPanel

비행체 자세(Attitude) 데이터를 분석하는 패널:
- Roll/Pitch/Yaw 시계열
- 자세 안정성 지표
- 비행 모드별 자세 변화 분석

## 9. 캐싱 및 성능 최적화

### 9.1 Redis 캐싱 전략

| 캐시 대상 | TTL | 캐시 키 패턴 | 이유 |
|----------|-----|-------------|------|
| CZML 데이터 | 5분 | `czml:{session_id}:{params_hash}` | 파라미터 조합별 캐싱, 빈번한 재생성 방지 |
| 히트맵 데이터 | 5분 | `heatmap:{session_id}:{params_hash}` | H3 집계 연산 비용 절감 |
| 기지국 데이터 | 24시간 | `towers:{session_id}` | 위치 추정은 변하지 않음 |
| KPI 데이터 | 5분 | `kpi:{session_id}` | 통계 연산 결과 캐싱 |

캐시 키의 `params_hash`는 쿼리 파라미터 조합의 MD5 해시로, 동일 조건 요청의 즉시 응답을 보장한다.

### 9.2 렌더링 성능 최적화

| 최적화 | 설명 | 효과 |
|--------|------|------|
| `requestRenderMode` | Cesium 프레임 요청 시에만 렌더링 | GPU 사용률 80% 절감 |
| 적응형 샘플링 | 데이터 크기별 자동 다운샘플링 | CZML 크기 최대 10배 절감 |
| RLE 경로 압축 | 연속 동일 색상 세그먼트 병합 | CZML 크기 추가 60% 절감 |
| 폴링 감소 | 세션 목록 폴링 간격 최적화 | API 호출 횟수 절감 |
| 히트맵 상호 배타 | LTE/Starlink/Combined 중 1개만 활성 | 동시 렌더링 부하 방지 |

### 9.3 응답 시간 목표

| 작업 | 캐시 미적중 | 캐시 적중 |
|------|-----------|----------|
| CZML 생성 | < 2초 | < 100ms |
| 히트맵 생성 | < 3초 | < 100ms |
| 기지국 추정 | < 5초 | < 100ms |
| KPI 산출 | < 1초 | < 50ms |
