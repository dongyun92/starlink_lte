## 🔍 6. 원인 분석 및 가설

### ❌ 배제된 원인

1. **위성 신호 품질** ❌
   - 고도각, 장애물, SNR, Packet Loss 모두 동일

2. **Roaming 상태** ❌
   - 둘 다 100% roaming

3. **Install Pending** ❌
   - 차이는 있지만 결정적이지 않음 (11.6%p)

### ✅ 유력한 원인 가설

#### 가설 1: Starlink 서비스 지역 경계 (가장 유력)
```
- Starlink는 서비스 지역(home country)과 roaming 지역을 구분
- 특정 GPS 좌표(지점 A, B)는 서비스 지역 경계 근처
- 해당 지점에서만 full-speed roaming 허용
- 나머지 구역은 throttled roaming (극도로 제한된 속도)
```

**증거**:
- 지점 A, B에서 **반복적으로** 좋은 성능 (4~5회)
- 동일한 시간대에서도 위치에 따라 성능 변화
- Roaming alert는 전 구간 활성화 (공식 roaming 지역)

#### 가설 2: 위성 Coverage Cell 경계
```
- Starlink 위성은 지상을 hexagonal cell로 나눔
- 각 cell은 독립적인 beam을 사용
- 특정 cell(지점 A, B 포함)만 roaming 우선순위 높음
- 다른 cell은 낮은 우선순위로 throttling
```

**증거**:
- 지리적으로 명확히 구분된 2개 지점
- 위성 방위각/고도각 차이 미미 (같은 위성 사용)

#### 가설 3: Ground Station 거리
```
- 지점 A, B가 가장 가까운 Starlink ground station 위치
- 다른 구역은 여러 hop을 거쳐야 해서 throttling
- Ground station routing policy 적용
```

**증거**:
- 특정 지점에서만 지속적으로 좋은 성능
- 하지만 latency는 오히려 좋은 구간이 더 높음 (반증?)
